# Task Spec V2 — Anti-Drift Anchoring Schema

> Breadcrumb: faerie2/docs/TASK-SPEC-V2.md | Phase: phase-003-anti-drift-anchoring

## Background — Why the Current Schema Fails

Chunk audit score: **0.49/1.0**. Atomicity (0.96) and dependency correctness (1.0) are working. The score is dragged down by two missing fields:

- `sizing` (maps to `estimated_effort`): **missing from ~96% of queued tasks**. Without it, `route_task()` defaults every task to Sonnet, burning 4x cost on work that Haiku could handle.
- `done_looks_like`: **missing from ~100% of queued tasks**. Without a machine-readable completion condition, agents drift — they finish the work they *think* is being asked for rather than the work that was queued. Observed failure mode: agent returns a manifest, main has to inspect output to determine success, burning main-side inference for work that should have been verified autonomously.

Tasks that have both fields (e.g., Plan Part 4 G1-G6) execute cleanly with zero main-side coordination. Tasks without them require main to synthesize ambiguous returns.

This document defines the V2 schema that closes both gaps.

## Schema Reference

```yaml
# TASK SPEC V2 — all fields
id: string
  # Format: task-{ISO_TS}-{slug}  or  task-{topic}-{n}
  # Examples: task-20260424-151200-honey-probe  |  task-eval-032
  # Machine-generated by cmd_add(); callers may override with a stable slug.

goal_one_line: string ≤80 chars
  # Imperative voice. One verb + one object. No ambiguity.
  # Bad:  "improve memory routing"
  # Good: "wire honey_hit_rate probe in 9x_session_metrics.py"

description: string ≥30 chars
  # Multiline permitted. Answer: WHY does this task exist? HOW should it be done?
  # Minimum 30 chars enforced at validation gate.

done_looks_like:                    # MANDATORY — one of the four flavors below
  acceptance_test: string           # shell command; exit=0 means done
  artifact_paths: list[string]      # files/dirs that must exist post-completion
  forensic_query: string            # grep/jq against forensics/ that returns non-empty
  prose_criteria: string ≥40 chars  # fallback; must be explicit and measurable

estimated_effort: enum [S, M, L, XL]
  # S  = ≤5 min  → Haiku (simple lookups, file reads, format conversions)
  # M  = 5–15 min → Sonnet (moderate analysis, single-file edits, targeted probes)
  # L  = 15–60 min → Sonnet (multi-file changes, synthesis, cross-repo work)
  # XL = >1 hour  → Sonnet background (architecture changes, migration scripts, full audits)

tags: list[string] ≥3
  # Domain tags for stigmergic routing and broadcast cross-pollination.
  # Examples: [memory, instrumentation, eval]  |  [queue, infra, validation]
  # Used by: 9x_broadcast_scan.py tag filter, queue-summary high_frontier routing

priority: enum [HIGH, MEDIUM, LOW]
  # HIGH:   blocks other work or fixes an active regression
  # MEDIUM: normal sprint work
  # LOW:    background / polish / deferred

phase_id: optional string
  # Binds task to a phase definition at forensics/phases/{id}.json.
  # Example: phase-003-anti-drift-anchoring
  # Used for phase-level progress rollups and completion gating.

blockedBy: list[string]
  # task_ids that must reach status=completed before this task is claimable.
  # Queue ops enforces this at claim time (unclaimed + blockedBy==[] required).
  # Example: ["task-spec-v2-validation-gate", "task-spec-v2-bundle-render"]

agent_type_hint: optional string
  # Suggestion for orchestrator. Not enforced — route_task() may override.
  # Examples: python-pro  |  data-engineer  |  documentation-engineer

artifacts_expected: optional list[string]
  # Paths the agent MUST produce. Checked by manifest validator post-completion.
  # If any path is missing, task cannot be auto-marked complete.
  # Example: ["/mnt/d/0local/gitrepos/faerie2/scripts/9x_task_retrofit.py"]
```

## Field-by-Field Rationale

### `id`

**Failure mode prevented:** Without a stable id, agents cannot discover predecessor work via `grep -r "_{task_id}_" forensics/`. The task_id-in-filename convention (Principle 3) depends on a queryable id at queue time — not assigned at claim time.

**Rule:** Generate at `add` time. Stable slugs preferred for long-lived tasks; timestamp-suffix for ephemeral tasks.

### `goal_one_line`

**Failure mode prevented:** Vague goals like "improve memory routing" cause agents to interpret scope differently across retries. An imperative verb + object ("wire X in Y") eliminates interpretation variance.

**Constraint:** ≤80 chars so it fits in a `dashboard_line` without truncation.

### `description`

**Failure mode prevented:** Agents spawned with only `goal_one_line` lack the why — they optimize for the stated output without understanding the context that would reveal whether a simpler path exists.

**Minimum 30 chars** enforced to prevent placeholder descriptions.

### `done_looks_like` — The Anti-Drift Anchor

This is the field that prevents agent drift. Without it, agents self-certify completion based on internal judgment. With it, completion is either machine-verifiable or explicitly scoped in prose.

**Four flavors (in order of preference):**

**1. `acceptance_test` (best — fully queryable)**

A shell command that exits 0 when the task is done.

```yaml
done_looks_like:
  acceptance_test: "grep -c honey_hit_rate /mnt/d/0local/gitrepos/faerie2/scripts/9x_session_metrics.py | grep -v '^0$'"
```

The command can be run by the agent before returning its manifest, by a hook after manifest write, or by faerie before marking a task complete. It is the strongest form because it requires no interpretation.

**2. `artifact_paths` (strong — existence-verifiable)**

A list of files or directories that must exist after task completion.

```yaml
done_looks_like:
  artifact_paths:
    - "/mnt/d/0local/gitrepos/faerie2/scripts/9x_task_retrofit.py"
    - "/mnt/d/0local/gitrepos/faerie2/forensics/task-retrofit-flagged.md"
```

Checked by manifest validator at completion time. Missing paths fail the task automatically. Does not verify content quality — use with `prose_criteria` for content contracts.

**3. `forensic_query` (good — stigmergic)**

A grep or jq query against `forensics/` that returns non-empty on success.

```yaml
done_looks_like:
  forensic_query: "grep -r 'done_looks_like' /mnt/d/0local/gitrepos/faerie2/forensics/manifests/ | wc -l | awk '{if ($1 >= 3) exit 0; else exit 1}'"
```

Used when the evidence of completion lives in the forensic chain — audit results, COC entries, or manifest fields — rather than in a specific file.

**4. `prose_criteria` (fallback — explicit prose)**

Human-readable completion criteria. Minimum 40 chars. Must be explicit and measurable — not "task is done" but "7x_queue_ops.py rejects tasks missing done_looks_like with an error message that includes an example of a valid spec."

```yaml
done_looks_like:
  prose_criteria: >
    7x_queue_ops.py add_task() rejects tasks missing done_looks_like field;
    rejection message includes an example of a valid spec;
    existing tasks in the queue are not rejected (warn-only, backward-compat).
```

`prose_criteria` is the escape hatch for tasks where a machine-readable test cannot be written at queue time (e.g., "produce a well-structured narrative"). The agent reads it before returning its manifest and must be able to self-certify against it.

**Multiple flavors can coexist.** When both `acceptance_test` and `artifact_paths` are present, both must pass.

### `estimated_effort`

**Failure mode prevented:** Without this field, `route_task()` defaults all tasks to Sonnet. S-sized tasks (simple lookups, format conversions, file reads) could run on Haiku at ~1/4 the cost and ~2x the speed.

**Routing table:**

| Size | Duration | Model | Use case |
|------|----------|-------|----------|
| S | ≤5 min | Haiku | File reads, grep queries, format conversions, single-value lookups |
| M | 5–15 min | Sonnet | Single-file edits, targeted probes, moderate analysis, short scripts |
| L | 15–60 min | Sonnet | Multi-file changes, cross-repo synthesis, medium scripts |
| XL | >1 hour | Sonnet background | Architecture changes, migration of 100+ tasks, full audit sweeps |

**Rule:** Estimate at queue time. Agents may escalate (S→M) if work expands, but must log the escalation in their manifest.

### `tags`

**Failure mode prevented:** Without domain tags, `9x_broadcast_scan.py` cannot route cross-session droplets to relevant tasks, and the `high_frontier` in `queue-summary.json` cannot surface tasks by domain without parsing full goal text.

**Minimum 3 tags** enforced to prevent degenerate tag lists.

**Convention:** Use nouns. Prefer single-word tags. Combine for compound domains: `[spawn, contract, enforcement]` not `[spawn-contract-enforcement]`.

### `phase_id`

**Failure mode prevented:** Without phase bindings, phase-level progress rollups require scanning all tasks by goal text. Explicit `phase_id` enables `forensics/phases/{id}.json` to be updated atomically at task completion.

Optional. Omit for tasks not belonging to a named phase.

### `blockedBy`

**Behavior (already enforced):** `claim_atomic()` checks `blockedBy == []` before allowing a claim. Tasks with unresolved deps cannot be claimed.

**Rule:** List only direct task_id dependencies, not phase dependencies. If task B requires task A's output, `blockedBy: [task-A-id]`. Do not use phase_id values here.

### `agent_type_hint`

Advisory. `route_task()` reads this as a preference, not a constraint. Use when the task type is strongly typed (e.g., only a `python-pro` should touch the hook enforcement code).

### `artifacts_expected`

Absolute paths the agent must produce. Checked by manifest validator after `status=final`. If any path is missing, the task is flagged for review rather than auto-completed.

Useful when `done_looks_like.artifact_paths` would be redundant — `artifacts_expected` is checked by infrastructure; `done_looks_like.artifact_paths` is checked by the agent itself before returning its manifest. Both can be specified for belt-and-suspenders coverage.

## Worked Examples

### Example 1 — Weak (current state)

```json
{
  "id": "task-20260420-103200-a3b1",
  "goal_one_line": "improve memory routing",
  "description": "Fix the memory system",
  "priority": "MED",
  "status": "queued"
}
```

**Problems:**
- `done_looks_like`: missing. Agent self-certifies. Returns when it "feels" done.
- `estimated_effort`: missing. Defaults to Sonnet regardless of actual scope.
- `tags`: missing. Cannot route via broadcast scan.
- `description`: 14 chars — no why, no how.

**Failure mode observed:** Agent edits 3 files, updates a metric name, and returns a manifest saying "memory routing improved." Main has to read the manifest output section to determine whether the correct metric was changed. Main burns inference; task was S-sized but ran on Sonnet.

### Example 2 — Strong (V2 spec)

```json
{
  "id": "task-20260424-151200-honey-probe",
  "goal_one_line": "wire honey_hit_rate probe in 9x_session_metrics.py",
  "description": "9x_session_metrics.py currently tracks context_pct and agent counts but not memory hit rate. Add honey_hit_rate field: ratio of HONEY reads that returned a relevant result (non-empty) to total HONEY reads in the session. Hook reads ~/.claude/HONEY.md access log (already written by memory_collector). Field emitted at every statusline update.",
  "done_looks_like": {
    "acceptance_test": "grep -c 'honey_hit_rate' /mnt/d/0local/gitrepos/faerie2/scripts/9x_session_metrics.py | awk '{if ($1 >= 1) exit 0; else exit 1}'",
    "prose_criteria": "honey_hit_rate field appears in statusline output; value is a float 0.0–1.0; metric is computed from HONEY access log, not hardcoded."
  },
  "estimated_effort": "M",
  "tags": ["memory", "instrumentation", "eval"],
  "priority": "HIGH",
  "phase_id": "phase-003-anti-drift-anchoring",
  "blockedBy": [],
  "agent_type_hint": "python-pro",
  "artifacts_expected": [
    "/mnt/d/0local/gitrepos/faerie2/scripts/9x_session_metrics.py"
  ]
}
```

**Result:** Agent reads task, runs `acceptance_test` before returning manifest, finds it exits 0, returns `dashboard_line: "honey_hit_rate probe wired; test passes; metric 0.0-1.0 float"`. Main reads dashboard_line only. Zero main-side coordination.

### Diff — what changed

| Field | Weak | Strong |
|-------|------|--------|
| `goal_one_line` | "improve memory routing" | "wire honey_hit_rate probe in 9x_session_metrics.py" |
| `description` | "Fix the memory system" | 4 sentences: what, why, where, how |
| `done_looks_like` | (missing) | acceptance_test + prose_criteria |
| `estimated_effort` | (missing → Sonnet) | M → Sonnet (correct, but explicit) |
| `tags` | (missing) | [memory, instrumentation, eval] |
| `artifacts_expected` | (missing) | [9x_session_metrics.py] |
| Main coordination required | Yes (inspect output) | No (dashboard_line sufficient) |
| Model cost | Sonnet (defaulted) | Sonnet (correct, intentional) |

### Example 3 — S-sized task correctly routed to Haiku

```json
{
  "id": "task-20260424-160000-queue-count",
  "goal_one_line": "report count of unclaimed tasks per priority in sprint-queue.json",
  "description": "One-shot read of sprint-queue.json; count tasks where status=queued and claim_state=unclaimed; group by priority; print JSON to stdout. No writes required.",
  "done_looks_like": {
    "acceptance_test": "python3 /mnt/d/0local/gitrepos/faerie2/scripts/7x_queue_ops.py list | grep 'QUEUED'"
  },
  "estimated_effort": "S",
  "tags": ["queue", "reporting", "haiku"],
  "priority": "LOW",
  "blockedBy": []
}
```

`estimated_effort: S` routes this to Haiku. Wall-clock time: ~90 seconds. Cost: ~$0.002. Without `estimated_effort`, Sonnet runs this same query for ~$0.008 and takes the same time.

## Migration Path — Retrofitting 144 Unclaimed Tasks

Current queue: ~144 unclaimed tasks with missing `done_looks_like` and `estimated_effort`.

**Proposed tool: `9x_task_retrofit.py`**

```
scripts/9x_task_retrofit.py
  --queue  PATH_TO_SPRINT_QUEUE_JSON
  --model  haiku                        (cheap; 144 tasks × ~500 tok = ~72K tok total)
  --dry-run                             (preview changes without writing)
  --flag-threshold  40                  (flag tasks whose description < 40 chars for human review)
  --output-flagged  forensics/task-retrofit-flagged.md
```

**Algorithm per task:**

1. Read `goal_one_line` + `description` + existing `blockedBy` + `tags`.
2. Haiku pass: infer `estimated_effort` (S/M/L/XL) from goal complexity and description length.
3. Haiku pass: synthesize `done_looks_like.prose_criteria` from goal + description. If description is ≥30 chars and contains measurable signal, generate an `acceptance_test` (grep-based where applicable).
4. Infer `tags` if missing: tokenize goal_one_line + description, match against known domain vocabulary.
5. If description < 40 chars or goal is ambiguous (no clear object), flag for human review instead of auto-inferring.
6. Write updated task back to queue (atomic via `_acquire_lock`).
7. Append flagged tasks to `forensics/task-retrofit-flagged.md`.

**Expected outcome:**
- >80% of unclaimed tasks get `done_looks_like` + `estimated_effort` populated automatically.
- ~15–20% flagged for human review (these are genuinely ambiguous tasks that should be redescribed anyway).
- Queue chunk audit score: 0.49 → target 0.85+ after retrofit.

**Backward compatibility:** Retrofit tool never deletes existing fields. It only adds missing ones. Tasks with existing `done_looks_like` are skipped.

## Validation Gate — `add_task()` Enforcement

Starting with V2, `7x_queue_ops.py add` must **reject** tasks missing `done_looks_like`.

### Rejection behavior

```
ERROR: Task rejected — missing required field: done_looks_like

At least one of these is required:
  --done-acceptance-test "shell command; exit=0 = done"
  --done-artifact-paths "/path/to/file,/path/to/other"
  --done-forensic-query "grep/jq query against forensics/"
  --done-prose-criteria "Explicit prose ≥40 chars describing completion"

Example (acceptance_test):
  python3 7x_queue_ops.py add \
    --goal "wire honey_hit_rate probe in 9x_session_metrics.py" \
    --done-acceptance-test "grep -c honey_hit_rate scripts/9x_session_metrics.py | awk '{if (\$1>=1) exit 0; else exit 1}'" \
    --estimated-effort M \
    --tags "memory,instrumentation,eval" \
    --priority HIGH
```

### Warn-only fields (incremental rollout)

Missing `tags` or `estimated_effort`: emit a WARNING to stderr but do not reject. This allows existing automation that calls `add` without these fields to continue working while the ecosystem migrates.

```
WARNING: Task added without estimated_effort — will default to Sonnet routing.
         Add --estimated-effort [S|M|L|XL] to enable cost-optimal model selection.
WARNING: Task added without tags — stigmergic routing and broadcast scan disabled for this task.
         Add --tags "tag1,tag2,tag3" to enable domain routing.
```

### Backward compatibility for existing tasks

The validation gate applies only at `add` time (new tasks). Existing tasks in the queue are not rejected on read. The retrofit tool adds missing fields to existing tasks separately.

### Implementation target

`cmd_add()` in `scripts/7x_queue_ops.py` — add validation before `_enforce_dead_reckoning_bundle()`. Task: `task-spec-v2-validation-gate`.

## Spawn Template Integration

The bundle renderer (`7x_spawn_template.py`) must inject the **full task spec** into agent context — not just `goal_one_line`.

### Current behavior (gap)

The template renderer injects `task_id`, `goal_one_line`, and `context_bundle` from the queued task. Fields like `done_looks_like`, `estimated_effort`, `tags`, and `artifacts_expected` are stored in the queue but not rendered into the agent's bundle.

**Effect:** Agent sees "wire honey_hit_rate probe in 9x_session_metrics.py" but not the `acceptance_test` that defines what "done" means. Agent self-certifies based on internal judgment.

### Required behavior (V2)

Bundle must include a task spec block:

```
TASK SPEC:
  id: task-20260424-151200-honey-probe
  goal: wire honey_hit_rate probe in 9x_session_metrics.py
  estimated_effort: M
  tags: [memory, instrumentation, eval]
  done_looks_like:
    acceptance_test: "grep -c 'honey_hit_rate' .../9x_session_metrics.py | awk '{if ($1 >= 1) exit 0; else exit 1}'"
    prose_criteria: "honey_hit_rate field appears in statusline output..."
  artifacts_expected:
    - /mnt/d/0local/.../9x_session_metrics.py

COMPLETION PROTOCOL:
  Before returning your manifest, run the acceptance_test above.
  If it exits non-zero, the task is not complete.
  artifacts_expected paths must all exist.
  Report done_looks_like outcome in your manifest under verification_result.
```
