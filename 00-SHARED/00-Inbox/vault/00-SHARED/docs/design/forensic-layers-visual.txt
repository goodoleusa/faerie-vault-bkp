# Forensic System Layers — Visual Architecture

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        FAERIE2 FORENSIC SYSTEM LAYERS                       │
└─────────────────────────────────────────────────────────────────────────────┘

LAYER 1: RAW EVIDENCE (IMMUTABLE BASELINE)
════════════════════════════════════════════════════════════════════════════════

  Evidence Files (CSVs, JSONs, HTMLs, PDFs, etc.)
        ↓ [HASH]
  genesis_manifest.json (SHA256 of each file)
        ↓ [RECORD]
  forensics/coc.jsonl entry #1 (type: genesis)

  Properties: Write-once, hash-chained, git-tracked
  Read by: data-engineer (ingest only)
  Cannot be modified: only versioned replacements allowed


LAYER 2: EVIDENCE STORE (TRACKED CHANGES)
════════════════════════════════════════════════════════════════════════════════

  {repo}/forensics/
  ├── coc.jsonl ............................ (append-only, hash-chained)
  ├── audit-log.md ......................... (human-readable FSL)
  ├── manifests/
  │   ├── genesis_manifest.json ........... (baseline hashes)
  │   ├── rawdata_manifest_{RUN}.json .... (ingest phase hashes)
  │   └── evidence_manifest.json ......... (current inventory)
  └── exports/ ............................ (court-ready bundles)

  Every entry in coc.jsonl:
    - entry_hash = SHA256(entry fields)
    - prev_entry_hash = SHA256 of previous entry
    → Chain is unbreakable; any change breaks downstream

  Immutability rule: NEVER git rm, git reset, or overwrite


LAYER 3: REASONING LOG (ANALYSIS STEPS)
════════════════════════════════════════════════════════════════════════════════

  ~/.claude/memory/investigations/{inv_id}/reasoning.jsonl

  Each agent run:
    {
      "agent": "data-scientist",
      "phase": "STAT_ANALYST",
      "input_hash": "sha256:abc123...",
      "output_hash": "sha256:def456...",
      "ts": "2026-04-07T14:23:47Z"
    }

  Properties:
    - Append-only (agents write findings here)
    - NOT CANONICAL (working hypotheses)
    - Used for REPLAYABILITY (re-run with input, verify output)
    - Does NOT feed coc.jsonl (reasoning ≠ evidence)


LAYER 4: MEMORY (ACCRETING KNOWLEDGE)
════════════════════════════════════════════════════════════════════════════════

  NECTAR: ~/.claude/memory/NECTAR.md
    ├─ Sprint summaries (findings, hypotheses, open questions)
    ├─ Append-only forever (narrative grows)
    ├─ NOT COMPRESSED (every entry permanent)
    └─ Promoted from agent findings at /handoff

  HONEY: ~/.claude/memory/HONEY.md
    ├─ Crystallized facts (durable knowledge)
    ├─ Compressed + contextualized (N findings → 1 bullet)
    ├─ COC entry created: type=crystallize
    └─ Only source of truth for system-level learnings

  Relationship: NECTAR (raw) → crystallize → HONEY (distilled)


LAYER 5: VAULT (HUMAN-READABLE SYNC)
════════════════════════════════════════════════════════════════════════════════

  $CT_VAULT/00-SHARED/Design-Narratives/
  ├── forensic-system-design.md (this file's parent doc)
  ├── forensic-implementation-checklist.md
  ├── forensic-schema-reference.json
  └── [investigation-specific docs]

  Vault is:
    ✓ Human-readable (Obsidian formatting)
    ✓ Synced to collaborators (Syncthing)
    ✓ NOT CANONICAL (derived from forensics/)
    ✓ Mutation-tracked (vault-mutation-tracker.py logs changes to coc.jsonl)


LAYER 6: CLOUD BACKUP (IMMUTABLE WORM)
════════════════════════════════════════════════════════════════════════════════

  B2 bucket (WORM protection enabled)
  ├── /forensics/ (complete backup of {repo}/forensics/)
  ├── /evidence/ (complete backup of raw evidence)
  ├── /exports/ (court-ready bundles)
  └── [versioned snapshots per commit]

  Properties:
    - Write-Once-Read-Many (WORM) — deletion prohibited
    - Versioning enabled — all prior states recoverable
    - Indexed by git commit hash
    - Survives total repo loss


════════════════════════════════════════════════════════════════════════════════
                              INFORMATION FLOW
════════════════════════════════════════════════════════════════════════════════

START INVESTIGATION
        │
        ↓
    [LAYER 1] RAW EVIDENCE INGESTED
        │
        ├─→ HASH all files
        ├─→ create genesis_manifest.json
        └─→ COC entry #1: type=genesis
        │
        ↓
    [LAYER 2] EVIDENCE STORE (forensics/)
        │
        ├─→ coc.jsonl starts growing
        ├─→ audit-log.md records every action
        └─→ manifests track all versions
        │
        ↓
    [LAYER 3] AGENTS ANALYZE
        │
        ├─→ Read evidence (READ-ONLY)
        ├─→ Produce findings
        └─→ Log reasoning steps (reasoning.jsonl)
        │
        ↓
    [LAYER 4] MEMORY PROMOTION
        │
        ├─→ Findings promoted to NECTAR (validated)
        ├─→ COC entry: type=promote
        └─→ HIGH flags → REVIEW-INBOX
        │
        ↓
    [LAYER 4b] CRYSTALLIZATION
        │
        ├─→ Multiple findings → 1 HONEY entry
        ├─→ COC entry: type=crystallize
        └─→ Sources documented
        │
        ↓
    [LAYER 5] VAULT MIRROR
        │
        ├─→ Design docs written
        ├─→ vault-mutation-tracker logs changes
        └─→ Synced to collaborators
        │
        ↓
    [LAYER 6] EXPORT → COURT
        │
        ├─→ Collect all forensic logs
        ├─→ Assemble evidence bundle
        ├─→ PGP sign
        ├─→ Upload to B2 WORM
        └─→ COC entry: type=export

════════════════════════════════════════════════════════════════════════════════
                        HASH CHAIN VISUAL (EXAMPLE)
════════════════════════════════════════════════════════════════════════════════

Entry #1 (Genesis)
  entry_hash = SHA256(...) = "abc123"
  prev_entry_hash = "genesis"

Entry #2 (Ingest Phase 1)
  entry_hash = SHA256(...) = "def456"
  prev_entry_hash = "abc123"  ← POINTS TO ENTRY #1

Entry #3 (Ingest Phase 2)
  entry_hash = SHA256(...) = "ghi789"
  prev_entry_hash = "def456"  ← POINTS TO ENTRY #2

Entry #4 (Agent Run)
  entry_hash = SHA256(...) = "jkl012"
  prev_entry_hash = "ghi789"  ← POINTS TO ENTRY #3

Entry #5 (Promote Finding)
  entry_hash = SHA256(...) = "mno345"
  prev_entry_hash = "jkl012"  ← POINTS TO ENTRY #4

                              ↓

If someone modifies Entry #2:
  - Its entry_hash changes
  - Entry #3's prev_entry_hash no longer matches
  - Chain BREAKS
  - Tampering is DETECTED
  - ALL downstream entries are invalidated


════════════════════════════════════════════════════════════════════════════════
                           COURT ADMISSIBILITY
════════════════════════════════════════════════════════════════════════════════

To admit evidence:

✓ Prove authenticity:    PGP signatures + timestamps
✓ Prove completeness:    Hash chain unbroken + no gaps
✓ Prove integrity:       SHA256 hashes match (bit-for-bit comparison)
✓ Prove chain of custody: audit-log.md documents every handler
✓ Show reproducibility:  reasoning.jsonl enables re-run with inputs
✓ Verify storage:        B2 WORM shows permanent, unmodified copy

Result: Evidence is admissible under Federal Rules of Evidence 803(6) (business record exception).
