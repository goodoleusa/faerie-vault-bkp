### What IS Working (evidence-grounded)

These are not aspirational — they are filesystem state that can be verified today.

**2. Rules architecture (core/sauce split) is implemented**

Evidence: `.claude/rules/` contains 13 files in a flat structure. The global `~/.claude/rules/` enforces the split with `core/` (always-loaded) and `sauce/` (on-demand). The principle is wired: sauce rules are never loaded at startup, reclaiming ~4.9K tokens per session.

**3. Memory system conflict eliminated (HIGH confidence: 0.90)**

The native Claude auto-memory override rule is in place in `~/.claude/rules/core/memory.md` with explicit override statement. MEMORY.md in the project folder is now a 12-token redirect. The two-system conflict (faerie pipeline vs native auto-memory) is structurally resolved.

**4. Droplet protocol as PRIMARY stigmergy driver (HIGH confidence: 0.85)**

The droplet check protocol was refined to read LIVE-*.md files from the past 3 days only. This is documented in `agent-lifecycle.md` (project rules) with explicit scope: "Time window: Past 3 days only." The scope prevents context clobbering while preserving the live pulse signal.

### What is NOT Yet Working / Blocking Issues

**1. Fresh-session baseline NOT yet measured (CRITICAL gap, confidence: 1.0)**

The narrative document explicitly states: "Awaiting fresh session baseline measurement to confirm sustainability." No agent has run a clean W1→W2→W3 cycle in a fresh session after the f(0) changes and measured actual T0% and piston wave count. The 8% claim is modeled, not observed.

**2. 91 tasks queued, 0 completed archived (HIGH concern)**

The consolidation agent found sprint-queue.json holds 91 active tasks with 0 recently completed. This means the queue is stale-accumulating rather than flowing. A healthy piston should be draining tasks across waves. Stagnation in the queue is a signal that either the piston isn't running free sessions or task completion is not being marked.

**3. 5 auto-memory fragments (MED concern)**

The consolidation result identified 5 auto-memory fragments from different session paths. These create fragmented memory that the context-manager needs to merge. Until merged, agents in new sessions may read incomplete or conflicting memory.

**4. Script renaming: 28 scripts named without tier prefixes (MED concern)**

The script audit (`wave2-script-audit-result.json`) shows 28 scripts need renaming per equilibrium rules. Until renamed, `9b_equilibrium_audit.py` will report violations. This is not blocking piston operation but blocks claiming "equilibrium is clean."

**5. "Half-crystallized state" risk flagged (MED concern)**

The f(0) orchestrator flagged a "half-crystallized state risk." Some rules consolidation work was captured in droplets/pollen but not yet crystallized into HONEY or NECTAR. These insights exist in the session's droplet stream but haven't entered the durable memory pipeline. Risk: they evaporate if the droplets aren't collected at /handoff.

**6. Core/sauce split in project rules is legacy flat (LOW concern)**

The project-level `.claude/rules/` folder is still flat (no `core/` subdirectory). The global `~/.claude/rules/` uses the proper `core/sauce/` structure. The project rules will be auto-loaded in their entirety on agent startup, which is slightly wasteful but not critical since the global rules take precedence.
